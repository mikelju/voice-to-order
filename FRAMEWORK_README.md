# SDD-WAT Framework

## What is this

A framework for developing software with AI agents (Claude Code) in a structured, predictable way. It combines two systems:

- **SDD (Spec-Driven Development)**: before writing code, WHAT to build is defined in a functional specification. The agent implements against that spec, not against improvised instructions.
- **WAT (Workflows, Agents, Tools)**: optional, for projects with repeatable tasks. It separates the instructions (workflows) from the execution (Python scripts).

The result: instead of asking the agent "build me a login" and correcting it for hours, you give it a precise spec and the agent builds exactly what you need.

---

## How it works

The framework defines a clear flow for each phase of the project:

```
/4-specify     →  define WHAT to build (functional spec)
       ↓
/5-plan        →  define HOW to implement it (phase plan)
       ↓
/6-implement   →  execute the plan step by step (test-first cycle)
       ↓
/7-verify      →  check that the code meets the spec
```

Each step generates documentation that feeds the next one. The spec defines the acceptance criteria, the plan turns them into steps with associated tests, `/6-implement` executes each step with the test → fail → code → pass cycle, and `/7-verify` checks that everything is aligned.

## The commands

They are invoked with `/` from Claude Code. Each one has a specific purpose:

| Command | What it does | When to use it |
|---------|----------|---------------|
| `/prime` | Loads the full project context | At the start of every session |
| `/1-create-master-plan` | Defines the product phases | When starting a new project |
| `/2-scaffold` | Creates the base project structure | After creating the master plan |
| `/3-init-project` | Generates CLAUDE.md by reading the real code | After creating the project scaffold |
| `/4-specify` | Generates the functional spec for a phase | Before starting each phase |
| `/5-plan` | Generates the implementation plan | After the spec, before coding |
| `/6-implement` | Executes the plan steps (test-first) | After the plan is approved |
| `/7-verify` | Checks spec ↔ code alignment | When finishing a phase |
| `/8-audit` | Security audit (phase or full project) | When closing a phase, before a release |
| `/9-document` | Generates a user guide from the specs | When finishing a phase or the project |

The full protocols are in `.claude/commands/`. The quick reference is in `.claude/commands/README.md`.

## The templates

Each document type has a template in `docs/templates/`. The commands read them when generating new documents. If you want to change a document's format, you edit the template and every command uses the new version.

| Template | What it generates | Which command uses it |
|-----------|------------|-------------------|
| `CLAUDE_project.md` | The project's CLAUDE.md | `/3-init-project` |
| `0_master_plan.md` | Master plan with phases | `/1-create-master-plan` |
| `X.spec.md` | Functional spec for a phase | `/4-specify` |
| `X.0_phase_plan.md` | Implementation plan | `/5-plan` |
| `X.tasks.md` | Atomic tasks (optional) | `/5-plan` |
| `X.Y_deviation.md` | Deviation record | `/6-implement` |
| `fix-N_name.md` | One-off bug fix | Manual |

## File structure

This is what a project using this framework looks like:

```
my-project/
├── CLAUDE.md                  # Project constitution (generated by /3-init-project)
├── .claude/commands/          # The commands + README
├── src/                       # Source code
├── tests/                     # Automated tests
├── docs/
│   ├── plans/                 # SDD documentation + plans
│   │   ├── 0_master_plan.md   # Global vision — phases and status
│   │   ├── phase_1/
│   │   │   ├── 1.spec.md     # Functional spec (WHAT)
│   │   │   ├── 1.0_name.md   # Phase plan (HOW)
│   │   │   └── 1.Y_*.md      # Deviations (if any)
│   │   └── fixes/
│   │       └── fix-N_*.md    # One-off bug fixes
│   └── templates/             # Document templates
├── .env                       # Environment variables
└── .gitignore
```

## Full project flow

### Kickoff (once)

```
1. /1-create-master-plan   →  define what you are building and in which phases
2. /2-scaffold             →  initialize the project (pip init, npm create, etc.)
3. /3-init-project         →  generate CLAUDE.md from the real code
```

### Each phase (repeat)

```
4. /4-specify              →  functional spec: WHAT + WHY
5. /5-plan                 →  implementation plan: HOW (user reviews and approves)
6. /6-implement            →  code + tests step by step (test-first)
7. /7-verify               →  check spec ↔ code alignment → mark [x]
8. /8-audit                →  security audit (phase scope, or full as release gate)
9. /9-document             →  user guide (optional, when finishing phase or project)
```

### Each work session

```
/prime                     →  load context before starting
```

## How to deploy this framework in a new project

### Step 1: Global system prompt
Copy the content of `CLAUDE_GLOBAL.md` into your global CLAUDE.md (the one injected as the system prompt in all projects).

### Step 2: Commands
Copy the entire `.claude/commands/` folder to your system. The commands are invoked with `/` from any project.

### Step 3: Templates
Copy the `docs/templates/` folder into the `docs/templates/` directory of each new project. The commands read them from that path when generating documents.

### Step 4: Verify
1. Run `/1-create-master-plan` → it should generate the master plan from the template
2. Run `/2-scaffold` → it should create the base project structure
3. Run `/3-init-project` → it should generate CLAUDE.md
4. Run `/4-specify` → `/5-plan` → `/6-implement` → `/7-verify`

## WAT framework (optional)

WAT is only needed if the project has **repeatable tasks** (scraping, reporting, data pipelines). For standard web applications or APIs, SDD + plans is enough.

If WAT is used, these folders are added:

```
workflows/          # Process instructions (Markdown)
tools/              # Execution scripts (Python)
docs/learnings/     # Lessons learned per workflow
```

The full details of WAT are in `CLAUDE_GLOBAL.md`, section "WAT framework (optional)".
