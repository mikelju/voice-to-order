# Phase 1: Anonymized dataset + verification

> Functional spec: `docs/plans/phase_1/1.spec.md`
> This plan implements the requirements defined in the spec above.

## Goal

Generate `data/` (catalog ~31k, history ~1k, extraction pairs) from the real data with a
deterministic, irreversible tool (HMAC with an external salt), and leave the guarantee as a runnable
check (`verify_anonymization.py`) in green.

- [x] US-1: deterministic anonymization tool with env vars, manual-review report
- [x] US-2: public verification tool (structural) + `--terms` mode (external list)
- [x] US-3: complete `data/`, referentially consistent, provenance README, verification green

## Notes / technical decisions

- **HMAC-SHA256 with an external salt** (not a plain hash): without the salt one can neither reverse
  nor *verify* a candidate real id against a token (resists dictionary attacks on ids with a known
  format). Salt in `ANON_SALT`, outside the repo. 10 hex = 40 bits — enough for 31k ids without
  expected collisions; the tool aborts on collision.
- **Dictated text is sanitized with rules + an external list + human review**: rules alone cannot know
  every proper noun — Whisper spells the same site name differently in every audio, so new variants
  can always appear. The candidates report (capitalized / out-of-vocabulary tokens) forces the human
  step.
- **Catalog descriptions also pass term+phone sanitization** (found during the real run: admin rows
  embed a contact name + mobile number, employee names, the supplier and an end customer). The
  proper-noun heuristic is NOT run over the catalog (31k ALL-CAPS product rows would flood the
  report); the catalog is covered by the terms sweep + structural phone/secret checks instead.
- Tests use **synthetic fixtures**: tests run in public CI; they never touch real data.
- The real catalog's "dirty" rows (empty/administrative descriptions) are kept: they are evidence of
  the real matching problem (decision aligned with portfolio case study 06).

## Real-run record

First real run hardened the pipeline (all covered by the final green gate):
- 3 Whisper spelling variants of one site name caught by the manual-review report (none was on any
  pre-existing list);
- PII embedded in catalog admin rows (contact name + phone) → description sanitization + a structural
  phone check;
- two extra order-reference formats found in dictated text (`11C208`, `11-3-6-6`) → regex extended,
  with tests.

Final numbers: 31,069 catalog rows (1 dropped no-id, 0 duplicate), 974 history rows (27 dropped
no-id, 0 orphan), 47 extraction pairs. Gate: 16 checks, 0 FAIL (incl. the 27-term sweep over the
whole repo).
