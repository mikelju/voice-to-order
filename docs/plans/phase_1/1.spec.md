# Spec Phase 1: Anonymized dataset + verification

> Functional specification — WHAT to build and WHY.
> The HOW is defined in the phase plan (1.0_anonymized_dataset.md).
> Acceptance criteria are verified with `/7-verify` at the end of the phase.

---

## Problem and goal

**Problem**: the system replicates a production product whose data (a ~31k-article catalog, ~1k
dictated-order history rows, validated extraction pairs) is a real client's operational data. The
repo will be public: no data may enter without an **irreversible, verifiable, repeatable**
anonymization process (legal criteria in `docs/refs/legal-framework-anonymization.md`).

**Goal**: `data/` contains the complete anonymized dataset, generated by a deterministic tool and
verified green by another tool anyone can run.

---

## User stories

### US-1: Generate the anonymized dataset
**As** the project author (the only person with access to the real data),
**I want** a tool that reads the real data and writes its anonymized version into `data/`,
**so that** publication never depends on irreproducible manual edits.

**Acceptance criteria:**
- [x] `tools/anonymize_dataset.py` reads real paths and the salt from environment variables
      (`REAL_DATA_DIR`, `ANON_SALT`, `REAL_REPLACEMENTS_FILE`) and fails clearly when missing
- [x] Article ids → `ART-` + 10 hex of HMAC-SHA256(salt, real id): deterministic (same id → same
      token across runs and files) and irreversible without the salt
- [x] Catalog: supplier column dropped; last-purchase date → month (`YYYY-MM`); rows without a useful
      description kept verbatim (real dirty data is part of the evidence); descriptions pass
      term/phone sanitization (admin rows embed names and phone numbers) with numeric specs untouched
- [x] History: `order_number`, `user_id`, `created_at` dropped; `last_used` → month; dictated text
      sanitized (`[customer]`, `[site]`, `[order-ref]`, `[phone]`)
- [x] Extraction pairs (JSONL): same text-sanitization rules on transcription and items
- [x] The tool emits a report of proper-noun candidates NOT covered by the rules
      (`.tmp/manual_review.txt`) for human review before committing

### US-2: Verify the anonymization (runnable by anyone)
**As** a repo reviewer (recruiter, auditor, or the author before each commit),
**I want** a verification tool that walks `data/` and fails on any identifying leftover,
**so that** the anonymization guarantee is a runnable check, not a promise.

**Acceptance criteria:**
- [x] `tools/verify_anonymization.py data/` exits 0 only when every check passes
- [x] Structural checks with no terms list (public mode): id format (`ART-[0-9a-f]{10}`), absence of
      forbidden columns (supplier, order_number, user_id), `YYYY-MM`-only dates, secret patterns
      (API keys, JWT, connection strings), emails, phone numbers, order-reference formats
- [x] `--terms <file>` mode (real list outside the repo): term sweep with variants (case, accents,
      hyphens) over `data/` AND the whole repo (`--repo`)
- [x] Readable output: PASS/FAIL per check + summary; exit code != 0 on any FAIL

### US-3: Versioned dataset
**As** a repo user,
**I want** to find in `data/` the dataset ready to load into the local DB,
**so that** I can run the system without access to any real data.

**Acceptance criteria:**
- [x] `data/catalog.csv` (~31k rows: id_articulo, articulo, ultima_compra_mes)
- [x] `data/historical.csv` (~1k rows: user_text, catalog_description, id_articulo, frequency,
      last_used_month)
- [x] `data/extraction_pairs.jsonl` (transcription → expected-items pairs, sanitized)
- [x] `data/README.md` declares the real origin, the process, what changed and what did not (no real
      terms)
- [x] Referential integrity: every `id_articulo` in the history exists in the catalog
- [x] `verify_anonymization.py` green on the committed dataset (incl. `--terms` locally)

## Data contracts

### `data/catalog.csv`

| Field | Type | Constraints |
|-------|------|---------------|
| id_articulo | str | `ART-[0-9a-f]{10}`, unique |
| articulo | str | verbatim real catalog description (generic vocabulary; Spanish) |
| ultima_compra_mes | str/empty | `YYYY-MM` or empty |

### `data/historical.csv`

| Field | Type | Constraints |
|-------|------|---------------|
| user_text | str | sanitized dictated phrase (Spanish) |
| catalog_description | str | confirmed description |
| id_articulo | str | FK → catalog.csv |
| frequency | int | ≥1 |
| last_used_month | str | `YYYY-MM` |

**Invariants:**
- No `ART-…` token repeats for two distinct real articles (HMAC collision = abort)
- The same real article gets the same token in catalog, history and future phases (embeddings)

---

## Constraints

- The real data and the salt **never** enter the repo or its commits (the history will be public)
- The manual review of the proper-noun report is blocking before the first commit of `data/`
- Tools in Python stdlib (+`pytest` for tests); no new dependencies without asking
- The dataset's text is Spanish (the system serves Spanish technicians) — kept verbatim by design

## Anti-goals (what this phase does NOT do)

- It does NOT generate embeddings (Phase 4)
- It does NOT load the database (Phase 2)
- It does NOT publish audio in any form
- It does NOT invent synthetic data to "fill gaps" — what cannot be published is omitted and declared
