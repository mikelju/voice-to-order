# Phase 2: Local database (Postgres + pgvector)

> Functional spec: `docs/plans/phase_2/2.spec.md`

## Goal

Local Postgres+pgvector via docker-compose with the ported schema, the verbatim CTE/HNSW functions
and the anonymized dataset loaded by a tool.

## Success criteria

- [x] US-1: one-command DB with schema + verbatim functions
- [x] US-2: idempotent loader with `--check`
- [x] US-3: integration tests that skip without Docker and prove everything with it

## Implementation steps

- [x] Step 1: `db/docker-compose.yml` + `db/init/01_schema.sql` (extensions, tables, HNSW, trigram)
- [x] Step 2: `db/init/02_functions.sql` — `buscar_articulos` + `buscar_historicos` ported verbatim
      (comments translated; `embeddings.id_articulo`/`historico_embeddings.historico_id` joins as in
      the original)
- [x] Step 3: `tools/load_database.py` (psycopg, COPY-based, idempotent, `--check`)
      — test: `tests/db/test_database_integration.py`
- [x] Step 4: real run: `docker-compose up -d` + load + integration tests green

## Notes / technical decisions

- **Functions ported verbatim** is the point (they encode the production fix for the HNSW
  statement-timeout incident — see portfolio case study 06). Only changes: English comments; the
  original's `is_active` filter is kept (column defaults TRUE in the replica).
- `vector(256)`: dimension contract for Phase 4 (reduced-dimension `text-embedding-3-small`).
- Loader uses `COPY` for the 31k rows (sub-second) and runs inside one transaction:
  truncate-and-reload = idempotent.
- Port 5433 on the host to avoid colliding with any local Postgres.
