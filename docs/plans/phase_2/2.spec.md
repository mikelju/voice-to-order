# Spec Phase 2: Local database (Postgres + pgvector)

> Functional specification — WHAT to build and WHY.
> Acceptance criteria are verified with `/7-verify` at the end of the phase.

## Problem and goal

**Problem**: the original system's retrieval lives in Supabase Cloud (pgvector + the CTE RPC
functions). The replica must provide the same engine locally with zero cloud dependencies.

**Goal**: `docker-compose up -d` + `python tools/load_database.py` leave a local Postgres with the
ported schema, the verbatim CTE/HNSW functions, and the anonymized dataset loaded.

## User stories

### US-1: One-command local database
**As** a repo user, **I want** `docker-compose up -d` to bring up Postgres+pgvector with the schema
already applied, **so that** no manual SQL is ever needed.

**Acceptance criteria:**
- [x] `db/docker-compose.yml` uses the official pgvector image; data persists in a named volume
- [x] Init SQL applies on first boot: extensions (`vector`, `pg_trgm`), tables `catalogo`,
      `embeddings`, `historico_pedidos`, `historico_embeddings`, HNSW indexes
- [x] The two functions ported **verbatim** from the original (same names, signatures, CTE
      `ORDER BY <=> LIMIT match_count*3` pattern, `SET statement_timeout='30s'`):
      `buscar_articulos`, `buscar_historicos`

### US-2: Load the dataset
**As** a repo user, **I want** `python tools/load_database.py` to load `data/` into the DB,
**so that** the search engine has the real (anonymized) corpus.

**Acceptance criteria:**
- [x] Loads catalog (~31k) and history (~1k) idempotently (re-run = same final state)
- [x] Referential integrity enforced by FKs; load fails loudly on violation
- [x] Prints loaded counts; `--check` mode reports row counts without writing

### US-3: Integration tests
**As** the maintainer, **I want** integration tests against the local DB, **so that** schema and
functions are proven, not assumed.

**Acceptance criteria:**
- [x] Tests **skip cleanly when the DB is unreachable** (CI without Docker stays green)
- [x] With the DB up: counts match `data/`, FKs hold, both functions exist and run, the HNSW indexes
      exist, trigram search works

## Constraints / decisions

- **Embedding dimension fixed at 256** (`vector(256)`): `text-embedding-3-small` supports reduced
  dimensions; 31k × 256 × 4B ≈ 32 MB of committed vectors (Phase 4) keeps the repo clonable. The
  schema is the contract for Phase 4.
- Demo-mode free-text search (manual add) will use **pg_trgm** as the no-API fallback — the extension
  ships in this schema.
- New dependency: `psycopg[binary]` (the project's Postgres driver). Recorded here as the Phase-2
  dependency decision.

## Anti-goals

- NO embeddings generation (Phase 4) — `embeddings`/`historico_embeddings` start empty
- NO backend services (Phase 3)
- NO auth, NO Supabase emulation — plain Postgres
