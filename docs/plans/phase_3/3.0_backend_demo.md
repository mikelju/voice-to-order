# Phase 3: FastAPI backend (full pipeline in demo mode)

> Functional spec: `docs/plans/phase_3/3.spec.md`

## Objective

Port the original backend to `src/backend/app/` so the 7-step pipeline runs end-to-end
locally with no API keys (demo mode), with identical contracts, constants and failure
semantics; real-mode code paths exist and are unit-tested with fakes (activated in Phase 6).

## Notes / Technical decisions

- **Demo replay of extraction** uses `expected_items.description` as both `ARTÍCULO` (memory
  query) and `DESCRIPCIÓN` (catalog query): the pairs store the confirmed catalog lines, not
  the intermediate dictated text. Declared in the README (Phase 7); demo scores are optimistic.
- **Demo num_order**: `10001 + recording_id` so the simulated ERP can resolve a plant and the
  full ERP path is exercised; ids ending in 9 → `not_found` to exercise the warning path.
- **Demo ranking = deterministic fallback** (no recorded re-rank replays; the fallback is
  original production behavior). Real mode uses the literal re-rank prompt.
- **Upsert in both modes** (original: production only) — the learning loop is a core demo.
- Fixed consciously (documented deviations from the original): `embed_query` no longer blocks
  the event loop; `Fecha_ultima_compra` field actually populated (the original had a key
  mismatch that always sent null); `Optional` import bug; LOG_LEVEL configurable.
- Ported as-is on purpose: no `is_active` filter in manual catalog search; no token cache for
  the simulated ERP; status literals in Spanish (`exito`, `fallido`, `omitido`, `no_intentado`).
