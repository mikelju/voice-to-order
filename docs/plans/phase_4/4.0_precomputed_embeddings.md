# Phase 4: Precomputed embeddings

> Functional spec: `docs/plans/phase_4/4.spec.md`

## Objective

Generate, version and load real embeddings (text-embedding-3-small, dim 256) for catalog,
memory and demo queries, so demo-mode search is true vector search.

## Implementation steps

- [x] Step 1: `tools/emblib.py` — stdlib f32 file format (write/read) — test:
      `tests/tools/test_emblib.py` (round-trip, no network)
- [x] Step 2: `tools/generate_embeddings.py` — batched OpenAI calls (batch 1000, retry x3),
      writes `data/embeddings/{catalog,historical,queries}.{ids.txt,f32}`; `--verify` mode
      runs the recall checks against the DB — test: `tests/tools/test_generate_embeddings.py`
      (fake client, batching + file output)
- [x] Step 3: extend `tools/load_database.py` to load `data/embeddings/` when present —
      test: extended `tests/db/test_database_integration.py` counts
- [x] Step 4: run the generation (author key), load, run `--verify`, run the full suite —
      demo flow shows vector scores
- [x] Step 5: update master plan / CLAUDE.md; commit (data files included)

## Notes / Technical decisions

- File format over .npy/parquet: zero new dependencies, readable with `array` from stdlib.
- The query-embedding keys are the EXACT description strings used by the demo replay
  (`expected_items[].description`) — the search service looks queries up verbatim.
- Catalog rows with empty `articulo` are skipped (nothing to embed); load still succeeds.
