# Spec Phase 4: Precomputed embeddings

> Small phase (<1 day): objective + acceptance criteria + anti-goals.

## Problem and goal

**Problem**: demo-mode vector search currently relies on the pg_trgm fallback because the
`embeddings`, `historico_embeddings` and `query_embeddings` tables are empty.

**Goal**: real, committed embeddings (text-embedding-3-small, dimension 256) for the whole
catalog, the learned memory and the demo replay queries, loaded with the same one-command
flow — demo search becomes true vector search.

**API-key decision** (was pending in the master plan): resolved — the author authorized
using his OpenAI key for this one-off generation (estimated cost < $0.01 for ~400k tokens).

## Acceptance criteria

- [x] `tools/generate_embeddings.py` (WAT tool, author-run, needs `OPENAI_API_KEY`) embeds:
      catalog `articulo` (31,069), historical `user_text` (974), and the unique demo query
      texts from `extraction_pairs.jsonl`; writes versioned files under `data/embeddings/`
- [x] Versioned format is stdlib-readable: `<name>.ids.txt` (one key per line, UTF-8) +
      `<name>.f32` (N x 256 float32 little-endian); round-trip unit-tested without network
- [x] `python tools/load_database.py` also loads `data/embeddings/` when present (the repo
      quickstart stays at two commands); `--check` reports the three embedding counts
- [x] Recall verification: for a sample of memory rows, `buscar_historicos` with the row's
      own query vector returns that row at rank 1 (similarity ≈ 1.0); for demo queries whose
      text exactly matches a catalog description, `buscar_articulos` returns that article at
      rank 1 — automated in the tool's `--verify` mode and as a DB test (skips when empty)
- [x] Full demo flow now reports vector scores (no trigram fallback for replay queries)

## Anti-goals

- NO live embedding at request time in demo mode (that is real mode, Phase 6)
- NO re-rank replays (demo ranking stays the deterministic fallback — Phase-3 decision)
- NO compression/quantization beyond the 256-dim reduction (clarity over bytes)
