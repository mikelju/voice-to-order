# Phase 5: React frontend

> Functional spec: `docs/plans/phase_5/5.spec.md`

## Objective

Port the original SPA into `src/frontend` (React 19 + Vite + TS + Tailwind v4), minus
auth, plus the demo recording picker; clickable demo flow end to end.

## Implementation steps

- [ ] Step 1: scaffolding — package.json (react 19, react-media-recorder; vite 6, ts 5.8,
      tailwind v4 via @tailwindcss/postcss), vite/ts/postcss config, index.html, index.css
- [ ] Step 2: `types/api_models.ts` + `types.ts` (mirror of the backend Pydantic models)
      + `api/apiService.ts` (fetch, no auth headers; + `getDemoRecordings`)
- [ ] Step 3: leaf components ported: `DescriptiveDropdown`, `DataTable` (+QuantityInput),
      `useDebounce`, `CatalogSearchModal`, `StatusCard`
- [ ] Step 4: flow components: `DemoRecordingPicker` (new), `AudioUploader`,
      `AudioRecorderHandler`, `InitialOrderDetails`, `ArticleSelector` (sentinel fix),
      `FinalizeOrderForm`, `OrderSummaryAndSend`
- [ ] Step 5: `App.tsx` state machine (AppStep + DEMO_PICKER), branding, confirmation
      dashboard with forced PDF modal + ERP retry
- [ ] Step 6: `npm run build` clean; manual smoke against the local backend (browser);
      update CLAUDE.md / master plan; commit

Verification note: the frontend has no test framework (same as the original — recorded
as accepted debt); correctness is covered by the typed contract (tsc against the mirror
types), the clean build, and the manual smoke of the full demo flow.

## Affected files

`src/frontend/**` (new, ~18 files). `CLAUDE.md`, master plan.

## Notes / Technical decisions

- No auth: getAuthHeaders removed; apiService is plain fetch + `detail` error pattern.
- Demo picker is a new first-class input path (`GET /demo/recordings`); record/upload
  stay (deterministic replay by upload hash in demo mode).
- Ported as-is: email status inferred from `error_details.includes("Email:")` (same
  contract as the original); forced PDF modal; plazo = today+3 days.
- Conscious fixes vs the original (recorded): sentinel rows excluded on confirm; no
  stray "5" literal in CatalogSearchModal; dead SigninPage not ported.
