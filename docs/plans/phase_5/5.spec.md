# Spec Phase 5: React frontend

> Medium phase. Ported from the original SPA (React 19 + Vite + TS + Tailwind v4),
> mapped in full before writing this spec.

## Problem and goal

**Problem**: the pipeline runs but only via curl/tests — the multi-step review UI (the
human-in-the-loop step that defines the product) is missing.

**Goal**: `npm run dev` in `src/frontend` serves the ported multi-step UI against the
local backend; the complete demo flow is clickable end to end with no API keys.

## User stories / acceptance criteria

### US-1: Choose input and process
- [x] Demo picker (replica addition): a list of the 47 recorded orders (from
      `GET /demo/recordings`) lets the user pick one; it posts `process-audio` with the
      `recording_id` field
- [x] Recording (react-media-recorder, webm) and file upload (audio/*) are ported and work
      in demo mode (deterministic replay by upload hash)
- [x] Step 2 review screen ported: warnings banner, transcription, num_order + planta
      (with the "verified with ERP" badge when `planta_name_source === 'erp'`), extracted
      lines table (accented keys `CANTIDAD`/`ARTÍCULO`/`DESCRIPCIÓN`)

### US-2: Candidate review table (the HITL core)
- [x] `ArticleSelector` ported: groups `searched_articles` by original article text,
      builds rows with the top candidate preselected; `--- SIN OPCIONES ---` sentinel
- [x] `DataTable` + `DescriptiveDropdown` + `QuantityInput` ported as-is (searchable
      dropdown with multi-word AND filter, decimal quantities with Spanish comma)
- [x] `CatalogSearchModal` ported: manual add with 500ms debounce, min 3 chars
- [x] Replica fix (recorded): confirming selections excludes sentinel rows (id `-`) —
      the original would send them (latent bug, mapped)

### US-3: Finalize and send
- [x] `FinalizeOrderForm` ported: plazo default = today+3d, debounced (500ms) plant
      verification via `get-planta` (success / not_found / error states)
- [x] `OrderSummaryAndSend` ported: accented `items_for_history` payload, navigation
      gated on `pdf_download_data`
- [x] Confirmation dashboard ported: 3 `StatusCard` lights (ERP critical red/green,
      email inferred from `error_details` containing "Email:", history), forced PDF
      download modal (base64 data URI), "retry ERP" button when `erp_update_status ===
      'fallido'`, "new order" reset

### US-4: Replica identity
- [x] No auth (no Supabase): the original's login/JWT layer is out of scope (anti-goal)
- [x] Voice-to-Order branding with an explicit demo-mode banner; ERP card labeled
      "Integración ERP (simulada)"; no client names anywhere
- [x] `VITE_FASTAPI_BASE_URL` via `.env` (default `http://127.0.0.1:8000/api/v1`),
      `.env.example` committed
- [x] `npm run build` (tsc + vite) passes clean

## Anti-goals

- NO auth/login screens, NO Supabase client
- NO redesign: same UX, components ported as mapped (Tailwind utility classes)
- NO new state libraries (manual state machine in App.tsx, prop drilling — as original)
