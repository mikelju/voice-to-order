# Phase 6 — Real-mode live E2E run evidence

> Spec: `6.spec.md` · Plan: `6.0_real_mode_e2e.md`. This file is the executed-run evidence
> required by acceptance criterion 2. All data below is synthetic or already-anonymized
> public data (no biometrics, no real client/site/part numbers).

## What ran

- **Mode:** `APP_MODE=real` — every stage used live providers.
- **Models:** `whisper-1` (transcription), `gemini-2.5-flash` (extraction + re-rank),
  `text-embedding-3-small` dim 256 (query + new-memory embeddings).
- **Audio:** synthetic Windows TTS WAV (`.tmp/real_e2e_order.wav`, 639,008 bytes), a
  **fictional** dictated order generated by `tools/make_tts_audio.py`. The WAV is NOT
  committed (voice is biometric data — `docs/refs/legal-framework-anonymization.md`).
- **Date of run:** 2026-06-17.

**Deviation (documented):** the plan called for a second server on port 8020; this run
drove the real endpoints in-process (httpx `ASGITransport` + the real `lifespan`). It is
equivalent — same endpoints, same lifespan, same live models — and more reliable for
capturing structured evidence on Windows. The throwaway driver lives in `.tmp/` (not
committed). One bug was found and fixed in that driver only (not in product code): a
standalone `asyncio.run()` builds a Proactor loop before `main.py` sets the selector
policy, so psycopg's pool can't connect; the driver now sets
`WindowsSelectorEventLoopPolicy` before `asyncio.run`, exactly as `tests/conftest.py` does
for the suite.

## Observed behavior worth noting

- **Real ASR imperfection, absorbed by the pipeline.** Whisper misheard the spoken
  "90001" as `9001` and "latón" as "Leitán". The pipeline tolerated both: Gemini's domain
  prompt normalized "Leitán" back to `LATON` in the catalog-shaped description, and the
  vector search still matched the correct latón ball-valve at 0.90. This is exactly the
  demo-vs-real gap the README should make explicit: demo replays are clean; live ASR is
  not, and the downstream stages are what make it robust.
- **Learned-memory-first path exercised live.** The junta resolved from memory
  (`Historical_match=true`) re-validated against the live catalog — the 0.75 memory
  threshold path, not just the catalog path.
- **Live new-memory embeddings.** `send` embedded 4 new memory rows live (the learning
  loop), proving `embed_documents` end to end.
- **All scores ≥ 0.88** — live query embeddings vs the committed catalog embeddings are
  comparable because both use `text-embedding-3-small` at dim 256 (Phase-2 contract).

## Approximate cost per order

Dominated by Whisper. For this 4-line order (~40 s audio):

| Provider call | Count | Note |
|---|---|---|
| whisper-1 transcription | 1 | ~40 s audio |
| gemini-2.5-flash extraction | 1 | large prompt + JSON out |
| gemini-2.5-flash re-rank | 4 | one per article |
| text-embedding-3-small | ~12 | query (8) + new-memory (4), tiny |

Order of magnitude **≈ US$0.01 per order, Whisper-dominated**; extraction/re-rank are
fractions of a cent and embeddings are negligible. (README material for Phase 7 — figure is
approximate, not a billed measurement.)

## Reproduce

```bash
docker-compose -f db/docker-compose.yml up -d        # local DB with committed embeddings
python tools/make_tts_audio.py                        # synth WAV -> .tmp/ (not committed)
# .env: APP_MODE can stay demo; the opt-in test/driver force real mode themselves.
RUN_REAL_MODE_TESTS=1 pytest tests/realmode -v        # opt-in live test (needs API keys)
```

The full audio E2E above used a throwaway in-process driver (`.tmp/run_real_e2e.py`, not
committed); the committed automated coverage is `tests/realmode/test_real_e2e.py` (text
stages — extraction, live-embedding search, re-rank). The Whisper leg is evidenced here.
