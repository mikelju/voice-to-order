# Spec Phase 6: Real mode (live Whisper + Gemini) + E2E

> Small phase: the real-mode code paths were built and fake-tested in Phase 3; this phase
> activates and proves them live, and packages the E2E verification.

## Problem and goal

**Problem**: real mode (live transcription/extraction/re-rank/embeddings) exists in code
but has never run against live providers; the repo cannot claim it works.

**Goal**: with the user's own `.env` (`APP_MODE=real` + API keys), the pipeline runs the
live models end to end, verified by an executed E2E run and by opt-in automated tests.

## Acceptance criteria

- [x] `APP_MODE=real` activates: whisper-1 transcription, Gemini extraction (retry x3),
      live query embeddings (text-embedding-3-small dim 256), Gemini re-rank with the
      deterministic fallback, live embeddings for new memory rows. Delivery channels stay
      simulated (anti-goal: no real ERP/O365 in the public replica)
- [x] An executed live E2E run is recorded in `docs/plans/phase_6/6.1_real_run_evidence.md`:
      synthetic TTS audio (fictional order, no biometrics) → transcription → extraction →
      vector search with live query embedding → send (history row embedded live);
      evidence includes the per-stage outputs (sanitized) and observed behavior
- [x] Opt-in automated E2E: `tests/realmode/test_real_e2e.py` runs only with
      `RUN_REAL_MODE_TESTS=1` (spends API quota; skipped by default and in CI)
- [x] Approximate per-order cost documented (README material for Phase 7)
- [x] Demo-mode suite stays green and is unaffected by real-mode settings (116 passed,
      1 skipped — the opt-in real-mode module)

## Anti-goals

- NO real delivery channels (ERP/email stay simulated)
- NO recorded real audio in the repo (voice is biometric data; the E2E uses synthetic TTS
  and the wav is NOT committed)
- NO new prompts/models — only the ported ones, live
