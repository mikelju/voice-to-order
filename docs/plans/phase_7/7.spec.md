# Spec Phase 7: Security audit + public README + release gate

> Final phase. The system is functionally complete (demo + real modes, executed E2E).
> This phase makes the repo *publishable*: audited, documented, CI-checked, and swept for
> real terms before the first public push.

## Problem and goal

**Problem**: the repo will be **public** for recruiters/technical reviewers, but it has no
security audit on file, no recruiter-facing README, no CI, and the anonymization has only
been checked structurally — not yet against the full real-terms list nor across git
history.

**Goal**: a public-ready repository — a documented security audit with high/critical
findings resolved, a recruiter-oriented README, CI that runs the tests + the anonymization
gate, and an executed pre-push sweep (real-terms + git history) — with zero violations of
the NEVER list anywhere in code, docs, or commit messages.

## Acceptance criteria

- [x] Full `/8-audit` run over backend + tools + frontend; report in `docs/security/`
      with severity-ranked findings. Critical/High are fixed (or recorded as justified
      deviations); Medium/Low triaged.
- [x] Public `README.md` at the repo root: what the system is, demo vs real modes,
      2-command quickstart, what is real-anonymized vs synthetic data, link to portfolio
      case study 06. No client branding, no real identifiers.
- [x] CI workflow (`.github/workflows/`): installs deps, runs `pytest` (demo suite;
      DB-backed tests either run against a pgvector service or skip cleanly), runs
      `tools/verify_anonymization.py`, and a security step. Green.
- [x] Pre-push gate executed and documented: `verify_anonymization.py --terms <external
      list>` clean + git-history sweep clean (author-run with the external secrets). The
      first public push happens only after this gate passes.
- [x] No NEVER-list content anywhere (real names of client/customers/sites/suppliers, real
      part numbers, secrets, real audio) — in code, docs, or commit history.

## Anti-goals

- NO deployment/hosting, NO auth, NO real ERP/O365 — the replica stays local-only.
- NO real terms committed or left in git history (a deleted-but-historical term still
  leaks — gotcha #1).
- NO weakening the anonymization gate to make it pass (a NEVER rule).
- NO new product features — this phase is hardening, documentation, and the release gate.
